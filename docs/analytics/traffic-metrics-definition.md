# 방문자·트래픽 통계 기준

상태: 확정

관련 이슈: #137

시간대: Asia/Seoul

## 목적

방문자 통계의 이름과 계산 기준을 먼저 고정해 Grafana, 백엔드 API,
프론트엔드가 서로 다른 숫자를 표시하지 않도록 한다. 이 문서는 통계 저장 및
조회 구현의 기준이며, 원본 사용자 행동 이벤트 스키마를 변경하지 않는다.

## 현재 사용 가능한 이벤트 식별자

프론트엔드의 `logEvent`가 다음 식별자를 모든 사용자 행동 이벤트에 포함한다.

- `anonymous_id`: 브라우저 `localStorage`에 저장되는 익명 UUID 기반 식별자
- `visit_id`: 마지막 활동 후 30분이 지나면 새로 발급되는 방문 세션 UUID
- `company_id`: 로그인 토큰이 유효할 때 백엔드가 추가하는 회사 식별자
- `created_at`: 백엔드가 Asia/Seoul 기준으로 기록하는 이벤트 발생 시각

IP 주소, 이메일, 브라우저 지문은 방문자 식별에 사용하지 않는다.

## 공통 시간 기준

- 일별 통계의 날짜 경계는 KST 00:00 이상, 다음 날 00:00 미만이다.
- 활성 사용자 집계 구간은 정각을 기준으로 정렬한 5분 버킷이다.
  - 예: 10:00:00 이상 10:05:00 미만
- Grafana와 API에서 날짜를 받더라도 서버가 KST 날짜 경계로 변환한다.
- 저장 및 계산 과정에서 구간의 시작은 포함하고 끝은 포함하지 않는다.

## 지표 정의

### 오늘 순방문자

오늘 한 건 이상의 유효 이벤트를 보낸 서로 다른 `anonymous_id` 수다.

```text
COUNT(DISTINCT anonymous_id)
```

같은 브라우저에서 새로고침하거나 나갔다가 다시 들어와도 하루 동안 한 명으로
계산한다.

### 오늘 방문 횟수

오늘 한 건 이상의 유효 이벤트를 보낸 서로 다른 `visit_id` 수다.

```text
COUNT(DISTINCT visit_id)
```

마지막 활동 이후 30분 이내에 다시 활동하면 같은 방문이며, 30분을 초과하면 새
방문으로 계산한다.

### 현재 활성 사용자

조회 시각 직전 5분 동안 유효 이벤트를 보낸 서로 다른 `anonymous_id` 수다.
HTTP 연결 수나 열린 브라우저 탭 수를 의미하지 않는다.

### 5분 활성 사용자

정렬된 각 5분 버킷 안에서 유효 이벤트를 보낸 서로 다른 `anonymous_id` 수다.
한 버킷에서 여러 이벤트를 발생시켜도 한 명으로 계산한다.

### 오늘 최대 활성 사용자

오늘 생성된 5분 버킷별 활성 사용자 중 가장 큰 값이다.

```text
MAX(5분 버킷별 COUNT(DISTINCT anonymous_id))
```

### 일별 순방문자

각 KST 날짜의 서로 다른 `anonymous_id` 수다. 같은 방문자가 여러 날짜에
방문하면 각 날짜에 한 명씩 계산한다.

### 일별 방문 횟수

각 KST 날짜의 서로 다른 `visit_id` 수다. 날짜를 넘어 유지된 방문 세션은 이벤트가
발생한 각 날짜의 방문 통계에 포함한다.

### 일별 최대 활성 사용자

각 KST 날짜에 속한 5분 버킷별 활성 사용자 중 가장 큰 값이다.

### 회원 방문자

해당 기간에 `company_id`가 한 번 이상 확인된 방문자다. 회사별 회원 방문자 수는
서로 다른 `company_id` 수로 계산한다.

### 비회원 방문자

해당 이벤트를 수집할 당시 `company_id`가 없었던 방문자다.

한 방문자가 같은 날 비로그인 상태로 방문한 뒤 로그인할 수 있으므로 회원 방문자와
비회원 방문자 수를 단순히 더한 값은 전체 순방문자와 다를 수 있다.

### 재방문자

기준일 이전 날짜에도 한 번 이상 나타난 `anonymous_id`가 기준일에 다시 나타난
경우다. 당일 여러 번 방문한 것은 재방문자 판정에 영향을 주지 않는다.

## 유효 이벤트

방문자 집계에는 백엔드가 정상 접수한 고객 여정 이벤트를 사용한다.

- 봇, 헬스체크 및 서버 내부 요청은 프론트엔드 이벤트를 발생시키지 않으므로 제외한다.
- 유효하지 않은 스키마로 거부된 이벤트는 제외한다.
- 이벤트 전송은 best-effort이므로 네트워크 오류나 백엔드 재시작 시 소량이 누락될
  수 있다. 이 통계는 제품 운영 및 추세 확인용이며 정산 자료로 사용하지 않는다.

## 경계 사례

| 상황 | 계산 결과 |
| --- | --- |
| 같은 브라우저에서 새로고침 | 순방문자 1명, 같은 `visit_id`면 방문 1회 |
| 30분 이내 재접속 | 순방문자 1명, 방문 1회 |
| 30분 초과 후 재접속 | 순방문자 1명, 방문 2회 |
| 날짜를 넘겨 계속 이용 | 각 날짜의 순방문자에 1명씩 포함 |
| 다른 브라우저 또는 기기 이용 | 별도 익명 방문자로 계산 가능 |
| 쿠키·로컬 스토리지 삭제 | 새로운 익명 방문자로 계산 가능 |
| 시크릿 모드 이용 | 일반 브라우저와 별도 방문자로 계산 가능 |
| 비회원 방문 후 로그인 | 전체 순방문자는 1명, 회원·비회원 양쪽 분류에 포함 가능 |
| 여러 탭에서 동시에 이용 | 같은 `anonymous_id`라면 활성 사용자 1명 |

## 개인정보 및 보존 원칙

- 통계 저장소에는 `anonymous_id` 원문 대신 서버 비밀키 기반 해시를 저장한다.
- `company_id`별 행동 내역은 외부에 공개하지 않는다.
- 통계 API는 집계된 숫자만 반환하고 개별 방문자 식별자를 반환하지 않는다.
- 5분 활성 버킷의 방문자 키는 운영에 필요한 최소 기간만 보존한다.
- 보존 기간과 삭제 작업은 후속 저장 구조 구현 단계에서 확정한다.

## 노출 범위

### Grafana 운영 대시보드

- 현재 활성 사용자
- 오늘 순방문자와 방문 횟수
- 오늘 최대 활성 사용자
- 일별 순방문자, 방문 횟수 및 최대 활성 사용자
- 회원·비회원 방문 추이

### 서비스 프론트엔드

방문자 및 활성 사용자 수는 공개하지 않는다. 초기 서비스의 작은 이용자 수가 제품
가치를 왜곡할 수 있고 운영 지표를 외부에 노출할 필요도 없기 때문이다.

프론트엔드에는 별도 통계 API를 통해 신규 공고, 진행 중 공고, 마감 임박 공고 등
공고 자체의 통계만 제공한다.

## 후속 구현 단계

1. 방문자 통계 저장 구조와 중복 방지 로직
2. 방문자 통계 조회 서비스 및 내부 API
3. Grafana 방문자 대시보드
4. 공고 통계 조회 API
5. 프론트엔드 공고 통계 UI
6. 보존 기간, 집계 실패 관측 및 운영 안정화

각 단계는 이 문서의 정의를 변경하지 않고 구현한다. 정의 변경이 필요하면 먼저 이
문서를 수정하고 영향받는 API와 대시보드를 함께 갱신한다.
